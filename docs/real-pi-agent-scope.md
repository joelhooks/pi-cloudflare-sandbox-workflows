## Vision

A work item enters the app as intent plus policy. The control plane resolves a context capsule, discovers package metadata, checks entitlements, pins packages from Artifacts, and starts a **real Pi planner lane**. That planner lane runs with bounded context, no raw secrets, and a strict structured-output contract. It must produce a `DynamicWorkflowBlueprint`: generated XState machine, generated harness, selected packages, verification contract, output target, side-effect declarations, and review gates.

Package is the top-level saved primitive. A package is a repo-backed module rooted at `package.json`; context packs, workflow packs, tool packs, support packs, adapters, org kernels, and personal kernels are package categories. Discovery starts from package metadata and exported contracts, not whole content blobs. Full package mount or invocation happens only after entitlement, version pinning, manifest/hash verification, and trust policy.

The app pins the planner prompt, Pi transcript ref, `workflows/machine.config.json`, `workflows/machine.ts`, `workflows/harness.ts`, `run/verification-contract.json`, and `run/plan.json` before hot execution. If the plan is not pinned, nothing runs.

Execution is done by real agent worker lanes, with Pi worker lanes required for the first real scope. The fixed supervisor/safety envelope admits bounded hot lanes, hydrates each sandbox from pinned Artifacts, materializes only leased auth refs, runs Pi non-interactively or over RPC, streams events, commits lane outputs, and tears down or sleeps sandboxes. The generated XState machine owns run-specific order; the fixed app machine only supervises trust boundaries.

The domain term is agent lane, not Pi lane. Pi is the first production runtime family (`pi-agent-cli`, `pi-agent-rpc`, `pi-sdk-runPrintMode`). Future `think-framework` lanes should fit the same lane contract: prompt ref, transcript ref, runtime, sandbox/ref if applicable, output refs, receipt ref, status, and `realAgent: true`. `integration-test` is allowed only for local receipts and must carry `realAgent: false`.

All side effects go through capability leases. Discord, GitHub, Wzrrd, Linear, email, deploy, or anything else is not a tool permission. It is a leased operation bound to actor, resource, payload hash, expiry, review gate, secret ref, and receipt sink. Dry-run still leases. Real send/apply/deploy requires policy and review.

Verification is another real agent lane or deterministic verifier selected by the plan. It reads pinned outputs and the verification contract, then emits a structured result. Capture happens only after verifier acceptance or explicit human review. The final review page shows plan, machine, harness, package refs, transcript refs, lane receipts, verifier result, capability receipts, and redacted artifacts.

## Non-negotiable real scope

- Real Pi planner, not a hand-coded planner.
- Real Pi worker lanes, not local memory execution.
- Generated XState machine and harness pinned before execution.
- Cloudflare Artifacts as canonical package, plan, machine, harness, transcript, and receipt storage.
- Package manifests are the source of truth for discoverable exports and runtime surfaces.
- Durable Object capsule as the stateful supervisor.
- D1 as query/index/control-plane rows, not package storage.
- Capability leases for every side effect.
- Bounded hot concurrency with cold scheduled lanes.
- Review gates and verifier contracts before trust changes.
- No raw tokens in prompts, D1, R2, Artifacts, logs, or generated code. Sandbox env may receive leased runtime material only with matching redacted `AgentAuthLease` receipt metadata.

## Completion test

The app is real when a fresh work item can run:

```txt
intent
-> capsule
-> package discovery and pinning
-> Pi planner lane
-> pinned generated machine/harness/plan/verification contract
-> Pi worker lanes in Cloudflare Sandboxes
-> capability lease requests
-> verifier lane
-> review surface
-> Wzrrd proposal reconciliation
-> observability telemetry pack and structured high-cardinality logs
-> captured receipts
```

If any of those arrows is replaced by a memory adapter and still called done, it is fake.
